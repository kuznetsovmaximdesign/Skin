# Гайд по стилю технической документации

Это пример гайда. Замените его своим — сервис подмешивает эти правила в каждый запрос к модели.

## Язык и тон

- Пишем по-русски, нейтрально и по делу. Без маркетинга и восклицательных знаков.
- Обращаемся к читателю на «вы», без «мы сделали», «наш замечательный сервис».
- Одна мысль — одно предложение. Предложения короче 20 слов.
- Настоящее время: «сервис возвращает ответ», а не «сервис вернёт ответ».

## Структура

- У документа один заголовок первого уровня (`#`).
- Разделы идут в порядке: назначение → предварительные условия → шаги → примеры → ограничения.
- Инструкции оформляем нумерованным списком, перечисления — маркированным.
- Абзац — не длиннее 4 строк.

## Термины и оформление

- Названия параметров, файлов и команд — в обратных кавычках: `config.yaml`.
- Единый термин на всё семейство документов: «документ», а не «статья»/«материал».
- Версии пишем полностью: «версия 2.4.0».
- Даты в формате ГГГГ-ММ-ДД.

## Чего не делаем

- Не обещаем сроков и не пишем «скоро», «в ближайшее время».
- Не оставляем выдуманных значений. Если данных нет — ставим пометку `[уточнить]`.
- Не удаляем существующие разделы без прямого указания.
