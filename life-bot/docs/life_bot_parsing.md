# Логика разбора и промпты

## Порядок слоёв

Каждое входящее сообщение проходит слои сверху вниз и останавливается на первом, который дал результат.

**Слой 0. Сохранение.** Сообщение пишется в `inbox_raw` до любого разбора. Голос — сразу расшифровывается локальным whisper, транскрипт кладётся в `transcript`. Фото сохраняется на диск.

**Слой 1. Висящий вопрос.** Если в `pending_questions` есть открытая строка — сообщение считается ответом на неё. Разбирается только то поле, которое было неясно. Ничего нового не создаётся.

**Слой 2. Выученные шаблоны.** Проверка по `parse_patterns`. Ноль обращений к моделям, ответ мгновенный. Сюда же базовые числовые формы: «45300 км», «3200 руб», «84,1 кг».

**Слой 3. Haiku.** Классификация и извлечение полей из свободного текста. Основной рабочий слой.

**Слой 4. Sonnet.** Фото еды, фото документов, голосовые с несколькими фактами сразу.

**Слой 5. Провал.** `parse_state = 'unparsed'`, реакция 🤔, запись ждёт разбора инбокса.

---

## Общие правила для всех промптов

1. Ответ — только JSON. Без преамбулы, без пояснений, без markdown-ограждений.
2. Текущая дата, день недели и часовой пояс передаются в промпте всегда. Без них относительные даты («в пятницу», «через три недели») разбираются неверно.
3. Поле, которого нет в сообщении, — `null`. Никаких догадок и подстановок «по смыслу».
4. Одно сообщение может содержать несколько фактов — возвращается массив. Но один факт не разбивается на несколько записей.
5. `confidence` от 0 до 1 и список полей, в которых модель не уверена. Всё, что ниже порога, идёт в вопрос пользователю, а не в базу.
6. Тип записи выбирается только из списка. Категория — только из словаря или `null`.

## Промпт 1. Классификация текста (Haiku)

```
Ты разбираешь личные заметки на структурированные записи. Отвечай только JSON.

Контекст:
- Сейчас: {now_iso}, {weekday}, часовой пояс {tz}.
- Известные люди: {people_list}
- Категории: home (быт), health (здоровье), car (авто), docs (документы), personal (личное)

Типы записей:
- deadline — что-то нужно сделать к дате или напомнить
- metric — измерение: вес, пробег, шаги, показания счётчика, сумма заправки
- meal — еда, съеденное
- wish — хочу купить себе
- gift — идея подарка кому-то
- place — место, куда стоит сходить
- note — не подходит ни к одному типу

Правила:
- Поле, которого нет в тексте, — null. Не додумывай.
- Несколько фактов — несколько объектов в массиве.
- Один факт не разбивай на два объекта.
- unsure — список имён полей, в значении которых ты не уверен.

Формат ответа:
{"records":[{"type":"...","fields":{...},"confidence":0.0,"unsure":["..."]}]}

Текст: {text}
```

## Промпт 2. Сроки — отдельный разбор дат (Haiku)

Вызывается, когда тип определён как `deadline`, а дата не разобрана слоем 2.

```
Разбери дату из фразы. Отвечай только JSON.

Сейчас: {now_iso}, {weekday}, зона {tz}.

Верни:
{"due_at":"YYYY-MM-DD","remind_at":"YYYY-MM-DD","repeat":null,"confidence":0.0,"ambiguous":["..."]}

Правила:
- due_at — когда наступает событие.
- remind_at — когда написать пользователю. По умолчанию равно due_at.
- Если во фразе есть подготовка («напомни за месяц»), remind_at сдвигается, due_at остаётся.
- «В пятницу» без уточнения — ближайшая пятница, но добавь "weekday" в ambiguous.
- Год не указан и дата уже прошла в этом году — следующий год, добавь "year" в ambiguous.
- Ничего похожего на дату нет — все поля null, confidence 0.

Фраза: {text}
```

## Промпт 3. Еда по фото (Sonnet)

```
Оцени блюдо на фото. Отвечай только JSON.

Формат:
{"items":[{"dish":"...","grams":0,"kcal":0,"protein_g":0,"fat_g":0,"carbs_g":0}],
 "confidence":0.0,
 "unsure":["..."],
 "basis":"что видно на фото и что пришлось предположить"}

Правила:
- Оценка по фото приблизительна. Не изображай точность, которой нет.
- Не видно объём порции или состав соуса — скажи об этом в unsure и basis.
- Не додумывай масло, сахар и заправки, если их не видно; отметь это в basis.
- Несколько блюд на фото — несколько объектов в items.
```

## Честная оговорка по еде

Калории и белок по фотографии — это оценка, а не измерение. Реальная ошибка обычно составляет десятки процентов и растёт на блюдах со скрытым маслом, соусами и невидимым объёмом порции.

Практический вывод для отчётов: такие значения нельзя смешивать в одном ряду с точными данными и нельзя строить на них выводы о малых изменениях. Разница «78 против 82 грамм белка» внутри погрешности метода и ничего не означает. Разница «60 против 120» — означает.

Поэтому в базе у записи из фото всегда стоит `confidence`, а в отчёте ряд, собранный из фото, помечается как оценочный.

---

## Порог и вопросы

- `confidence` ниже 0.8 или непустой `unsure` — вопрос пользователю, запись не создаётся.
- Даты с непустым `ambiguous` — вопрос всегда, независимо от confidence.
- Открытый вопрос ровно один. Остальные ждут очереди.
- Нет ответа сутки — вопрос закрывается, запись уходит в инбокс.

## Обучение шаблонов

После каждого удачного разбора через Haiku, подтверждённого пользователем, нормализованная структура фразы кладётся в `parse_patterns`. При третьем совпадении шаблон начинает применяться без обращения к модели.

Смысл: чем дольше работает бот, тем меньше он тратит лимит подписки. Обратная связь — счётчик `hits` показывает, какие шаблоны реально работают, а какие записались зря.
