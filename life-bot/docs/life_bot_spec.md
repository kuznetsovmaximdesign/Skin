> Начни с этапа 1 из раздела «Порядок работ». Не переходи к следующему этапу, пока текущий не проходит приёмочные сценарии из последнего раздела.

## 1. Что строим

Личный Telegram-бот: единая точка, куда владелец скидывает всё подряд текстом, голосом и фото, а бот раскладывает это по структурированным разделам и напоминает о сроках.

Пользователь один. Второй не планируется, но `profile_id` проставляется везде с первого дня.

Приоритет качества: напоминания и заметки должны работать без осечек. Остальное вторично.

## 2. Среда

- Прод: хост не зафиксирован. Кандидат — домашний mini PC, VPS как приёмник бэкапов. Доступ по SSH.
- Python 3.11+, systemd-сервис с `Restart=always`.
- SQLite в WAL-режиме. Одна база, путь в конфиге.
- Claude Code CLI на том же сервере, работает от подписки владельца. Вызов только в headless-режиме: `claude -p --output-format json`.
- Версия CLI фиксируется. Обновление — только осознанное.
- Все секреты (токен бота, пути) — в отдельном файле с правами 600, не в исходниках.
- Время в базе хранится в UTC, отображается в Europe/Moscow.

## 3. Стек

| Задача | Библиотека |
|---|---|
| Каркас бота | aiogram 3 |
| Многошаговые окна с редактированием на месте | aiogram-dialog |
| Расписания | APScheduler, хранилище задач в той же SQLite |
| Разбор дат по-русски | dateparser |
| Повторяющиеся правила | python-dateutil, rrule (RFC 5545) |
| Расшифровка голоса | faster-whisper, локально |
| Внешний контроль живости | healthchecks.io |

Свой парсер дат и свой формат повторов не изобретать.

## 4. Данные

Схема — `docs/life_bot_schema.sql`, применяется как есть. Ключевые принципы, которые нельзя нарушать:

1. Входящее сообщение пишется в `inbox_raw` до любого разбора и не удаляется никогда.
2. Каждая запись ссылается на своё сырое сообщение через `raw_id`.
3. Один факт — одна запись одного типа. Связанные объекты соединяются через `links`, а не смешиваются в одной строке.
4. Категории берутся только из таблицы `categories`. Свободный ввод запрещён. Категория может быть пустой.
5. Правки пишутся в `record_edits`. Запись не переписывается молча.
6. Настройки читаются из таблицы `settings`, а не из констант в коде.

## 5. Разбор входящих

Логика и промпты — `docs/life_bot_parsing.md`. Порядок слоёв: сохранение → висящий вопрос → dateparser и выученные шаблоны → Haiku → Sonnet → инбокс.

Обязательно:
- Текущая дата, день недели и часовой пояс передаются в каждый промпт.
- `timeout` на вызов CLI, один повтор, `--fallback-model`.
- Каждый вызов логируется в `llm_calls`.
- Модель недоступна или лимит исчерпан — сообщение не теряется, встаёт в очередь.

## 6. Модули

### Напоминания — главный модуль

- Поля `due_at` (когда событие) и `remind_at` (когда написать). По умолчанию совпадают.
- Напоминание приходит в момент `remind_at`.
- Просроченное повторяется дважды в день в слотах из `overdue_slots`, пока не закроешь или не перенесёшь.
- Всё просроченное приходит одним сообщением списком, не по одному.
- Кнопки переноса: через час, завтра, через неделю.
- Повторяющиеся сроки бывают двух видов: `calendar` — жёсткая дата, пропуск график не двигает; `done` — следующий отсчитывается от фактического закрытия.
- Если запись просрочена больше суток, кнопка «сделал» раскрывается в «сегодня / вчера / в срок».
- Закрытая запись уходит в архив, из выдачи исчезает сразу, физически чистится через `archive_days`.

### Заметки

Свободный текст. Поиск по команде и голосом. Удаляются насовсем по кнопке — без архива.

### Покупки

Два списка: продукты и домой. Добавление пачкой из одной фразы. Отметка позиции вычёркивает её на месте. Очистка списка целиком.

### Вишлист, подарки, места, фильмы

Списки без дат. Отметка убирает позицию из выдачи. У подарков — связь с человеком и его датой рождения, которая порождает связанный срок. У мест — дата окончания для событий, после неё запись сама закрывается.

Для фильмов: хранить только то, что сказал пользователь. Год, режиссёра, жанр не дописывать.

### Еда

Фото блюда разбирается Sonnet. Итог дня в 22:00: белок и калории против целей из настроек. Записи из фото всегда с `confidence` — это оценка, а не измерение.

### Авто

Пробег вводится текстом или голосом. Бот считает средний километраж и прогнозирует ТО. Регулярно пробег не спрашивает — только когда прогноз подходит к порогу.

## 7. Поведение

Тексты — `docs/life_bot_replies.md`, воспроизводятся дословно.

- Тихие часы 00:00–09:00: бот не пишет по своей инициативе. Приём работает круглосуточно.
- Уверен — короткое подтверждение одной строкой. Не уверен — вопрос.
- Открытый вопрос ровно один. Следующее сообщение считается ответом на него. Есть кнопка «это новое». Через сутки вопрос закрывается сам.
- Даты в ответах словами, с сокращённым днём недели: `15 октября (чт)`.
- Один объект — одно живое сообщение. Мёртвых кнопок в чате не остаётся.
- Повторное нажатие той же кнопки не создаёт второе действие.
- Закреплённое сообщение-счётчик редактируется, а не пересылается.
- Инбокс разбирается при пяти неразобранных или через две недели, что раньше. Не больше пяти вопросов за сессию.
- Недельная сводка в воскресенье. Совет выдаётся только при трёх и более однотипных случаях, иначе только цифры. Каждый совет пишется в `findings`.

## 8. Нефункциональные требования

1. Сообщение не теряется никогда, ни при какой ошибке.
2. Идемпотентность: повтор callback, дубль сообщения в течение минуты.
3. Ежедневный бэкап базы на maxmini, зашифрованный. Ежемесячная проверка восстановления.
4. Heartbeat на healthchecks.io каждые пять минут. Упавший бот не может уведомить о себе сам — контроль только внешний.
5. Ротация логов. Ошибки не показываются пользователю, только пишутся в лог.
6. Фото еды чистятся через `photo_keep_days`. Фото бланков анализов хранятся вечно.
7. Экспорт всей базы в JSON по команде.

## 9. Порядок работ

**Этап 1. Труба.** Приём текста, голоса и фото. Всё падает в `inbox_raw`. Разбора нет. Реакция на сообщение. systemd, heartbeat, бэкап.

**Этап 2. Напоминания.** dateparser, таблица сроков, планировщик, слоты просрочки, кнопки, закрытие, повторы обоих видов. Без обращений к моделям.

**Этап 3. Слой Haiku.** Свободный текст, классификация, висящие вопросы, выученные шаблоны, лог вызовов.

**Этап 4. Заметки, покупки, списки.** Поиск, правка, удаление, экспорт.

**Этап 5. Еда и авто.** Sonnet по фото, итог дня, пробег и прогноз ТО.

**Этап 6. Отчёты.** Недельная сводка, советы с порогом, итог 90 дней.

Каждый этап заканчивается работающим ботом, а не заготовкой.

## 10. Чего не делать

- Не подключать Home Assistant. Убрано из скоупа.
- Не добавлять Ozon, рабочие задачи, дачу, изучение языков.
- Не делать веб-интерфейс. Он будет позже, отдельно.
- Не добавлять приоритеты, проекты, теги, геймификацию, серии и очки.
- Не додумывать данные, которых не было в сообщении.
- Не писать бодрых формулировок и не ставить эмодзи в текстах.

## 11. Приёмочные сценарии

Этап считается сданным, когда все сценарии проходят.

**Этап 1**
1. Текст, голосовое и фото — все три попали в `inbox_raw` с корректным `kind`.
2. Сервис убит принудительно — systemd поднял его, healthchecks не успел сработать.
3. Бэкап создан, развёрнут в отдельную копию, данные совпадают.

**Этап 2**
4. «Напомни 15 октября про ОСАГО» — создан срок, подтверждение содержит `15 октября (чт)`.
5. «Напомни в пятницу» — если пятница неоднозначна, бот задал вопрос, а не угадал.
6. Срок наступил — пришло напоминание. Не отреагировал — пришло повторно в 19:00, но не ночью.
7. Шесть просроченных — пришло одно сообщение списком, а не шесть.
8. Перенос через час в 23:30 — напоминание пришло в 09:00, а не ночью.
9. Просроченная на три дня закрыта кнопкой «вчера» — в базе стоит вчерашняя дата.
10. Календарный повтор закрыт с опозданием — следующий остался на исходной дате. Интервальный — сдвинулся от факта.

**Этап 3**
11. Фраза без явной структуры разобрана Haiku, тип определён верно.
12. Та же формулировка на третий раз разобрана без обращения к модели.
13. Модель недоступна — сообщение сохранено, пользователь получил «не разобрал, сохранил как есть».
14. На висящий вопрос отвечено голосовым — ответ применён к нужному полю, новая запись не создана.

**Этап 4**
15. «Молоко, хлеб, творог» — три позиции в списке продуктов, одним сообщением.

17. Заметка удалена — в базе её нет.
18. Экспорт вернул JSON со всеми таблицами.

**Этап 5**
19. Фото блюда — записаны белок и калории с `confidence`.
20. Пробег назван дважды — бот посчитал средний километраж и дал прогноз ТО.

**Этап 6**
21. Неделя с двумя однотипными переносами — совета нет, только цифры.
