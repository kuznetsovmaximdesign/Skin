# Личный бот

Telegram-бот для одного пользователя: заметки, напоминания, списки, питание.
Текст, голос, фото. Задание — в `docs/`, читать начиная с `docs/life_bot_spec.md`.

Сделаны этапы 1 и 2: приём входящих и напоминания. Разбора свободного текста
моделью ещё нет — это этап 3.

## Что уже работает

- Приём текста, голоса, фото, пересланных сообщений и файлов.
- Запись в `inbox_raw` с видом `text | voice | photo | forward` — до скачивания
  файла и до расшифровки. Сбой сети или whisper пишется в поле `error`,
  сообщение остаётся.
- Расшифровка голоса локальным faster-whisper. Выключается в конфиге.
- Фото и аудио складываются в `var/files/ГГГГ-ММ-ДД/<id файла>`.
- Реакция 👀 на принятое сообщение — единственный ответ на этом этапе.
- Повтор того же `tg_message_id` в течение минуты не создаёт вторую строку.
- Чужие сообщения игнорируются: бот отвечает только `telegram.owner_id`.
- Heartbeat на healthchecks.io, пока процесс жив.
- Systemd-юнит с `Restart=always`, ежедневный зашифрованный бэкап по таймеру
  и скрипт проверки восстановления — в `deploy/`, инструкция там же.

## Напоминания

- Даты по-русски: `15 октября`, `в пятницу`, `через час`, `завтра в 10 утра`,
  `15.10`, `20 числа`, `напомни за месяц до`, `каждый год`, `каждые 90 дней`.
  Сами даты разбирает dateparser; правилами добраны повторы, подготовка,
  время суток словами и числовые формы, которые библиотека не берёт.
- Неоднозначность не угадывается: `в пятницу` — это вопрос с кнопками,
  а не выбор наугад. Сутки без ответа — вопрос закрывается сам.
- Напоминание приходит в момент `remind_at` новым сообщением с кнопками:
  сделал, не напоминать, через час, завтра, через неделю.
- Просроченное повторяется в слотах из настроек (09:00 и 19:00) одним
  сообщением списком, а не по одному, и редактируется на месте.
- Тихие часы 00:00–09:00: перенос «через час» в 23:30 отдаёт напоминание
  в 09:00. Приём сообщений при этом круглосуточный.
- Просрочено больше суток — «сделал» раскрывается в сегодня / вчера / в срок.
- Повторы двух видов: `calendar` — от исходной даты, пропуск график не двигает;
  `done` — от факта закрытия.
- Закреплённый счётчик `Просрочено 2 · Сегодня 1 · Инбокс 3` редактируется,
  а не отправляется заново.
- Повторное нажатие той же кнопки второго действия не создаёт.

## Запуск

```
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/pip install -r requirements-voice.txt   # если нужен голос

cp config.example.toml config.toml
chmod 600 config.toml                              # секреты не в исходниках
$EDITOR config.toml                                # token и owner_id

.venv/bin/python -m life_bot
```

Путь к конфигу переопределяется переменной `LIFE_BOT_CONFIG`.
База, файлы и лог по умолчанию лежат в `var/` рядом с конфигом.

## Тесты

```
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest
```

Telegram и whisper в тестах заменены заглушками, сеть не нужна.

## Устройство

| Файл | Что делает |
|---|---|
| `life_bot/config.py` | Конфиг из TOML, проверка прав 600 |
| `life_bot/db.py` | SQLite в WAL, схема из `docs/life_bot_schema.sql` как есть |
| `life_bot/intake.py` | Слой 0: вид сообщения, запись, файл, расшифровка, реакция |
| `life_bot/voice.py` | faster-whisper, модель грузится лениво |
| `life_bot/dates.py` | Разбор русских дат и вывод словами |
| `life_bot/deadlines.py` | Сроки: создание, закрытие, перенос, повторы |
| `life_bot/reminders.py` | Отправка напоминаний, список просрочки, счётчик |
| `life_bot/scheduler.py` | APScheduler, хранилище задач в той же базе |
| `life_bot/questions.py` | Висящие уточнения |
| `life_bot/texts.py` | Тексты ответов, дословно из `docs/life_bot_replies.md` |
| `life_bot/router.py` | Обработчики сообщений и кнопок |
| `life_bot/bot.py` | Каркас aiogram, фильтр владельца, запуск |

## Выкат

См. `deploy/README.md`. Нужен Linux и Python 3.11+.

## Что проверено, а что нет

Локально проверено всё, кроме связи с Telegram: бэкап снимается, шифруется,
разворачивается обратно и сходится по числу записей — это приёмочный сценарий 3.

Не проверено на живой машине: сценарий 1 (три вида сообщений доходят до
`inbox_raw`) и сценарий 2 (systemd поднимает убитый процесс). Оба требуют
доступа к Telegram и к серверу.
