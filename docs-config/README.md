# docs-config — источник правды для правил

Сюда кладутся четыре артефакта разбора портала. Изменили файл — изменились правила,
код править не нужно. Сервис перечитывает файлы автоматически при изменении.

| Файл | Что задаёт |
| --- | --- |
| `article-type-schemas.json` | типы статей: обязательные секции, порядок, уровни заголовков, метаполя, профили |
| `markdownlint-rule-candidates.md` | стандартные коды markdownlint + список кастомных правил `KDOC-*` |
| `glossary.csv` | термбанк: термин → принятое написание → чего избегать → перевод / «не переводить» |
| `report.md` | контекст и обоснования; сервис его не разбирает, только показывает наличие |

**Файлы в этой папке сейчас — образцы формата.** Замените их своими: имена и структура
должны остаться теми же.

## Форматы

### `article-type-schemas.json`

```jsonc
{
  "version": 1,
  "profiles": ["legacy_help", "modern_help", "modern_kb"],
  "admonition_types": ["note", "warning", "important", "example"],
  "types": [
    {
      "type_id": "howto_procedure",
      "name": "Инструкция",
      "profiles": ["modern_help", "legacy_help"],   // где применим тип
      "required_sections": ["Назначение", "Порядок действий"],
      "enforce_order": true,
      "section_levels": { "Назначение": 2 },
      "required_meta": { "modern_help": ["article_id", "product"], "*": ["article_id"] },
      "detect": {                                    // эвристика, если типа нет во front-matter
        "headings_any": ["Порядок действий"],
        "title_prefix": ["Как ", "Чтобы "],
        "text_contains": []
      },
      "rules": { "KDOC-LEADIN": "error" },           // переопределение уровня правил для типа
      "lintable": true                                // false — документ вне текстовой проверки
    }
  ]
}
```

### `markdownlint-rule-candidates.md`

Свободный текст плюс два машиночитаемых куска:

- блок ```` ```jsonc ```` (или ```` ```json ````) с конфигурацией стандартных кодов markdownlint;
- строки с идентификаторами `KDOC-*`; уровень задаётся словами в строке:
  `рекомендация` / `warning` → предупреждение, `ошибка` / `error` → нарушение,
  `выключено` / `off` → правило отключено.

### `glossary.csv`

Заголовки распознаются гибко (русские или английские). Понимаются колонки:

`термин, принятое написание, избегать, перевод, не переводить, локаль, комментарий`

- «избегать» — список через `;`, каждое превращается в замену «X → принятое написание»;
- «не переводить» — `да`/`yes`/`1` помечает продуктовое имя, которое остаётся как есть;
- «перевод» — эквивалент в другой локали; неточное совпадение не считается ошибкой
  (асимметричная локализация), поэтому используется как справка, а не как жёсткое правило.
