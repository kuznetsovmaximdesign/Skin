# Кандидаты в правила оформления (ОБРАЗЕЦ ФОРМАТА)

Заменить файлом из разбора портала. Ниже — машиночитаемые части: блок конфигурации
стандартных кодов markdownlint и список кастомных правил `KDOC-*`.

## Стандартные коды markdownlint

```jsonc
{
  "default": true,
  "MD003": { "style": "atx" },
  "MD004": { "style": "dash" },
  "MD013": { "line_length": 120, "code_blocks": false, "tables": false },
  "MD024": { "siblings_only": true },
  "MD025": true,
  "MD029": { "style": "ordered" },
  "MD040": true,
  "MD041": true,
  "MD046": { "style": "fenced" }
}
```

## Кастомные правила

- `KDOC-ADMONITION-TYPE` — ошибка. У врезки должен быть явный машиночитаемый тип из списка
  (`note`, `warning`, `important`, `example`). Цвет и оформление типом не считаются.
- `KDOC-LEADIN` — ошибка, только `howto_procedure`. Перед нумерованными шагами нужен лид-ин
  вида «Чтобы …:», оканчивающийся двоеточием.
- `KDOC-RESULT` — рекомендация, только `howto_procedure`. После шагов нужен абзац-результат
  («В результате …»).
- `KDOC-UI-BOLD` — ошибка. Названия элементов интерфейса оформляются полужирным, а не кавычками.
- `KDOC-TABLE-FOR-PARALLEL` — рекомендация. Если подряд идут 3 и более однотипных пункта вида
  «Название — описание», используйте таблицу.
- `KDOC-FOOTER-META` — ошибка для профилей `modern_help` и `modern_kb`. В конце статьи должен быть
  блок метаданных (идентификатор статьи, дата обновления).
- `KDOC-ABBR-EXPANSION` — ошибка. Аббревиатура при первом употреблении расшифровывается,
  кроме продуктовых имён из глоссария.
- `KDOC-IMAGE-ALT` — ошибка. У изображения должен быть alt-текст и подпись.
- `KDOC-ESCALATION` — рекомендация, только `troubleshooting`. Открытый вопрос: обязателен ли
  раздел с порядком эскалации.
- `KDOC-CROSSLOCALE` — рекомендация. Структура статьи должна совпадать с другими локалями
  того же `article_id`.
